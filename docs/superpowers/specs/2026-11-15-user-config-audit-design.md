# User-config audit: `audit --user` checks the setup outside any repo

- **Status:** approved
- **Date:** 2026-11-15

## Purpose

`claude-kit:audit` and `claude-kit:audit-deep` check one repo's Claude
config (section 4 of `plugin/skills/audit/rules.md`). Most of a user's
real exposure is outside any repo: user settings and permissions,
user-scope and per-project MCP servers in `~/.claude.json`, third-party
plugin hooks and the scripts they run, skills-dir plugins, user skills
and scheduled tasks. Nothing checks those.

The idea comes from ECC's "AgentShield", which treats an agent's
configuration as an attack surface (an external Claude Code setup;
ideas only, no text copied). A companion spec,
`2026-11-15-untrusted-vault-content-design.md`, covers untrusted vault
content; the two share no code.

## Scope

**In:**
- `plugin/scripts/user-config-inventory.py` (new): lists the user-scope
  config as JSON (Design: Inventory).
- `tests/test_user_config_inventory.py` (new): tests on a fake home
  directory.
- `plugin/skills/audit/user-mode.md` (new): the `--user` procedure.
- `plugin/skills/audit/SKILL.md`: argument `--user` points at
  `user-mode.md`; the frontmatter description and `argument-hint`
  mention it.
- `tests/test_audit_skills.py`: assertions for the user mode.
- `knowledge/decisions/<NNNN>-user-config-audit.md` (new): the ADR,
  numbered one above the highest number in `knowledge/decisions/` on
  `origin/main` at implementation time, and its index row in
  `knowledge/decisions/README.md`.
- `README.md`: one sentence next to the existing audit description.
- `plugin/.claude-plugin/plugin.json`: minor version bump, one above
  the version on `origin/main` at implementation time.
- `tests/test_plugin_manifest.py`: the pinned version follows the bump.
- `docs/superpowers/README.md`: index rows for this spec and its plan
  (regenerated by `spec-index.py`).

**Out:**
- Fixing anything the user audit finds. Like the repo audit, it is
  read-only.
- `audit-deep`: it gains no user mode (D2).
- Changes to `rules.md` or `check-findings.py`: user mode states its
  one difference from `rules.md` itself (Design: Audit `--user` mode).
- Untrusted vault content (companion spec).

## Design

### Inventory

`plugin/scripts/user-config-inventory.py [--home DIR]`, standard library
only, Python 3.11, `sys.stdout.reconfigure(encoding="utf-8")`. `--home`
defaults to `Path.home()`. Prints one JSON object; every `file` is a
posix path relative to the home directory, and `line` is the 1-based
line in that file where the item appears, or null:

- `settings`: for `.claude/settings.json` and `.claude/settings.local.json`
  when present: `permissions` (each `allow`, `ask` and `deny` rule with
  file and line), `defaultMode`, `hooks` (event, matcher, command, file,
  line), `env` key names only (never values), `enabledPlugins`,
  `statusLine` (its command, file, line) and `autoMode` (its key names
  and file, line).
- `mcp_servers`: from `.claude.json`, the top-level `mcpServers` (scope
  `user`) and each `projects.<path>.mcpServers` (scope `local`, with the
  project path): name, type, command, args, url, and `env` and `headers`
  key names only.
- `plugins`: from `.claude/plugins/installed_plugins.json`: name,
  version, `gitCommitSha` when present, install path, whether enabled
  in `enabledPlugins`; and for each, its hooks from
  `<installPath>/hooks/hooks.json` (event, matcher, command, file, line)
  when present.
- `skills`: each `.claude/skills/<name>` entry, and whether it is a
  junction or symlink (and its target). When the entry's directory (or
  its target) holds `.claude-plugin/plugin.json`, the entry is marked
  `plugin: true` and its hooks from `hooks/hooks.json` are listed
  (event, matcher, command, file, line), as for installed plugins.
- `scheduled_tasks`: each `.claude/scheduled-tasks/<name>` folder and
  the files in it.
- `instructions`: `.claude/CLAUDE.md` when present (loaded into every
  session in every repo), and each file under `.claude/agents/`,
  `.claude/commands/` and `.claude/output-styles/`.

A missing file or key yields an empty list, not an error. Malformed
JSON yields an `errors` entry `{file, error}` and the rest is still
printed. Exit 0, or 2 when `--home` is not a directory.

### Audit `--user` mode

`plugin/skills/audit/SKILL.md`: when `$ARGUMENTS` is `--user`, read
`user-mode.md` in this skill's directory and follow it instead of the
repo passes. `user-mode.md` says:

- **Rules.** Read `rules.md` in full; its read-only, finding-format,
  hard-rule and self-check sections bind this mode, with one change:
  "repo root" is the home directory, paths in **Where** are relative to
  it, and `~/.claude/claude-kit/audit/` replaces `<repo>/docs/audit/`
  as the one folder section 1 lets the audit write to. The scratch-file
  rule is unchanged.
- **Inventory.** Run `user-config-inventory.py` (the plugin's scripts
  folder, with the usual `${CLAUDE_PLUGIN_ROOT}` fallback). Never read
  `.claude/settings.json`, `.claude/settings.local.json` or
  `.claude.json` in full: read only the line ranges the inventory
  cites, and never an `env` or `headers` block. Read in full every hook
  command's target script (the kit's, skills-dir plugins' and installed
  plugins'), the `statusLine` command's target script, skill files,
  scheduled-task files and every `instructions` file.
- **Checks.** Section 4 of `rules.md`, both halves, on every item; plus:
  permission rules broader than their apparent purpose and auto-approve
  modes; hooks that run on every tool call or prompt, or that fetch or
  run remote code; MCP servers with unpinned packages (`npx` or `uvx`
  without a version), remote URLs, or wide scope; plugins without a
  pinned commit; scheduled tasks that read untrusted content (web,
  inbox, vault ingest) with no human in the loop; untrusted text paths
  into a tool-using model across the whole setup.
- **Output.** `~/.claude/claude-kit/audit/user-config.md` (create the
  folder), never inside a repo, because it holds private paths and
  settings. Ask before overwriting an existing report. Header: date,
  home directory written as `~`, the `version` in the kit's
  `plugin.json`, and what was not read.
  Sections: `## Inventory` (tables), one section per area
  (Permissions, Hooks, MCP servers, Plugins, Skills, Scheduled tasks,
  Instructions),
  `## Fix first`. Never copy a secret or an env or header value.
- **Self-check.** Run `check-findings.py <home> <report>` until it
  exits 0. In chat: counts by severity, the top five from Fix first,
  the checker's summary line and the report path; open the report.

## Decisions

- **D1. User audit is a mode of `audit`, not a new skill.** (User's
  pick.) It reuses `rules.md` and `check-findings.py`. Rejected: a
  separate `config-audit` skill (duplicates both), and the inventory
  script alone (lists without judging).
- **D2. No user mode in `audit-deep`.** (My call.) The user-scope setup
  is small enough for one session.
- **D3. The report lives under `~/.claude/claude-kit/audit/`.** (My
  call.) A kit-owned folder under `~/.claude/` (created if absent),
  outside every repo: the report holds private paths
  and settings and must never land in a repo.
- **D4. Neither the inventory nor the audit reads env or header
  values.** (My call.) The inventory lists key names only, and the audit
  reads the settings files and `.claude.json` only at the cited lines,
  never an `env` or `headers` block, so secrets never enter the model's
  context.
- **D5. Nothing is frozen.** (My call.) The assertions go into test
  files this change creates or must edit, and the behavioural check
  (Success criterion 2) is a manual run.
- **D6. Split from untrusted vault content.** (Gate finding.) The two
  parts share no code, files or tests, so each ships and reverts on its
  own.

### ADR

The new ADR records D1, D3 and D4 (one sentence each on the reason and
the rejected option), in the format of
`knowledge/decisions/0000-template.md`.

## Testing

`tests/test_user_config_inventory.py` builds a fake home directory with
settings (with `statusLine` and `autoMode`), `.claude.json` (user and
project MCP servers, with env values), an installed plugin with a `hooks/hooks.json`, a skills-dir
plugin directory with `.claude-plugin/plugin.json` and
`hooks/hooks.json`, a plain skill, a scheduled task, a user `CLAUDE.md` and one file
each under `agents/`, `commands/` and `output-styles/`, and asserts:
every rule, hook, server and plugin is listed with the right file and
line; `statusLine` and `autoMode` are listed; the `instructions`
files are listed; the skills-dir plugin is marked `plugin: true` with its hooks;
env and header values appear nowhere in the output; a malformed
`settings.json` yields an `errors` entry and the rest still prints; a
missing home yields exit 2.

`tests/test_audit_skills.py` gains: `audit/SKILL.md` names `--user` and
`user-mode.md`; `user-mode.md` names `user-config-inventory.py`,
`~/.claude/claude-kit/audit/user-config.md`, `check-findings.py`,
"never inside a repo", that it never reads the settings files or
`.claude.json` in full, and that `~/.claude/claude-kit/audit/` replaces
`<repo>/docs/audit/`.

## Success criteria

Agreed evaluation and verification criteria:

1. **Suite green:** `pytest`, `ruff check plugin tests` and
   `ruff format --check plugin tests` pass, including every test above.
2. **User audit run (manual):** `audit --user` on this machine writes
   `~/.claude/claude-kit/audit/user-config.md`; `check-findings.py`
   exits 0 on it with the home directory as root; its inventory lists
   every plugin in `enabledPlugins`, every skills-dir plugin and every
   hook command; a search of the report for each env value in the user
   settings and each env and header value in `.claude.json` finds none. The report itself is not pasted in the PR
   (private); the PR states the counts by severity.
