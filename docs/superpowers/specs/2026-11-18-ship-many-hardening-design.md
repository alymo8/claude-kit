# `/ship-many` hardening: time limit, one resume, keep-awake

- **Status:** approved
- **Date:** 2026-11-18

## Purpose

The first real `/ship-many` run (2026-11-16 to 11-18) shipped two specs
(PRs 63 and 64) but no child finished in one go, and each restart was by
hand:

1. **Print mode killed a background test run.** A child that ran its
   full suite with `run_in_background` was cut off after 10 minutes (the
   print-mode wait ceiling, `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`), and
   the child ended before its PR. The hand resume, with that variable set
   to `0`, finished.
2. **The 2-hour limit was not enforced.** `/ship-many` step 4 gives each
   background Bash command a 2-hour timeout, but the Bash tool does not
   enforce a timeout on a `run_in_background` command: one child ran
   about 7 hours.
3. **Transient failures ended children.** Two API `ENOTFOUND` network
   drops each ended a child with no PR and no handoff. Each was resumed
   by running `claude -p "/claude-kit:ship <spec>"` from inside the
   child's feature worktree (`/ship` step 1 then goes to step 3).
4. **Laptop sleep paused a child for 6 hours.**
5. **Two specs took the same ADR number.** Both specs left the number as
   `<NNNN>` ("one above the highest on `origin/main` at implementation
   time"). The wave-2 child started while the wave-1 child had ended
   unmerged (failure 1), so both picked 0047; the second renumbered to
   0048 when it rebased, as `/ship` step 9 already prescribes.

This change makes failures 1 to 4 handle themselves and records why
failure 5 needs no new mechanism.

- `knowledge/kit-dev-gotchas.md`: under "Why `/ship` and `/ship-fast`

- `knowledge/decisions/<NNNN>-ship-many-child-runner.md` (new): the

  (regenerated by `spec-index.py`).

**Out:**
- An ADR-number reservation across specs or waves (D5).
- Holding later-wave specs when an earlier child ends unmerged (D5).
- Rerunning `/ship-many` over specs whose `feat/<slug>` branch already
  exists from an earlier run; resuming those stays a hand step.
- `/ship-fast` and a plain `/ship` run by the user: neither runs in
  print mode under `/ship-many`, so neither changes.
- Lid-close sleep: a keep-awake request does not override the lid
  action (D4).

## Design

### Child runner

`plugin/scripts/ship-child.py`, standard library only, Python 3.11,
`sys.stdout.reconfigure(encoding="utf-8")`:

```
python ship-child.py --spec <rel> --main <main checkout> --log <log dir> --name <log-name>
                     [--timeout 7200] [--resume-wait 60]
                     [--claude claude] [--gh gh] [--git git]
```

`<rel>` is the spec path relative to the main checkout with `/`
separators. `--claude`, `--gh` and `--git` name the executables (tests
pass fakes); the runner resolves each with `shutil.which` (so
`claude.cmd` is found on Windows). Exit 2 on bad usage, when `--main`
is not a directory, or when an executable is not found (message names
it).

1. **Keep-awake** for the runner's lifetime (D4): on Windows,
   `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` through
   `ctypes`, called and reset (to `ES_CONTINUOUS`, on exit) on the main
   thread, which waits on the children for the whole run; on macOS, start
   `caffeinate -i -w <runner pid>`; elsewhere, `systemd-inhibit
   --what=sleep --mode=block sleep infinity` when `systemd-inhibit` is
   on `PATH`, terminated on exit. When none applies or the call fails,
   continue and record `"keep_awake": false`.
2. **Attempt.** Run, with the environment plus
   `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` (D1):

   ```
   claude -p "/claude-kit:ship <rel>" --permission-mode auto --permission-prompts none --output-format json
   ```

   stdout to `<log>/<name>.json`, stderr to `<log>/<name>.err` (the
   resume writes `<name>.resume.json` and `<name>.resume.err`). The child
   starts in its own process group (POSIX: `start_new_session=True`;
   Windows: `CREATE_NEW_PROCESS_GROUP`). When `--timeout` seconds pass
   (D2), kill the child's whole process tree (Windows:
   `taskkill /PID <pid> /T /F`; POSIX: `SIGTERM` to the group, then
   `SIGKILL` after 10 seconds) and mark the attempt `timed_out`.
3. **Decide on a resume** after the first attempt (D3). The branch is
   `feat/<slug>` (Branch slug). Before the first attempt the runner
   records `git -C <main> worktree list --porcelain`. Take the first rule
   that applies:
   - The attempt timed out: no resume (`timed out`).
   - `gh pr list --head feat/<slug> --state merged --json number,createdAt`,
     run from `--main`, exits non-zero: no resume (`gh failed`). Without
     the PR state the runner cannot rule out a merged child, and a rerun
     would ship the spec twice.
   - It lists a PR whose `createdAt` is after the attempt start (both
     compared as timezone-aware UTC): no resume (`merged`).
   - A worktree on `refs/heads/feat/<slug>` was already in the list
     recorded before the first attempt: no resume (`no worktree`); a
     rerun over an earlier run's branch stays a hand step (Scope Out).
   - `git -C <main> worktree list --porcelain` now shows a worktree on
     `refs/heads/feat/<slug>` whose `.claude/handoffs/feat_<slug>.md`
     has a `- **Written:** ... by <by>` line with `<by>` other than
     `session-end snapshot`: no resume (`stop rule`). No time is
     compared: the previous rule skips any worktree that existed before
     the first attempt, so a handoff in this one comes from this run, and
     the `/handoff` `Written` time is typed by the model, not read from a
     clock. `/ship` writes such a line through the `claude-kit:handoff`
     skill only when a stop rule fires; the SessionEnd snapshot hook
     (`handoff_snapshot.py`) also creates or refreshes the file, but
     marks its own `Written` or `State refreshed` line
     `by session-end snapshot`, so the file's existence or modification
     time proves nothing.
   - That worktree exists: resume in it.
   - No such worktree, and `<main>/<rel>` exists: resume in the main
     checkout (no worktree was created; the spec is still in the main
     checkout).
   - Otherwise: no resume (`no worktree`).
4. **Resume.** Wait `--resume-wait` seconds, then run one more attempt
   as in point 2, in the chosen directory, with its own `--timeout`. No
   further attempts.
5. **Status.** Write `<log>/<name>.status.json`:

   ```json
   {"spec": "<rel>", "branch": "feat/<slug>", "keep_awake": true,
    "attempts": [{"cwd": "...", "start": "<UTC ISO>", "end": "<UTC ISO>",
                  "exit": 1, "timed_out": false, "cost": 4.12}],
    "resume": "resumed | merged | stop rule | timed out | gh failed | no worktree",
    "timed_out": false, "exit": 0, "cost": 9.30}
   ```

   An attempt's `cost` is `total_cost_usd` from its JSON file when the
   file holds a JSON object, else `null`. Top-level `exit` and
   `timed_out` are the last attempt's; `cost` is the sum of the non-null
   costs, or `null` when all are null. The runner's exit code is the last
   attempt's exit code (124 when it timed out).

### Branch slug

`/ship` step 2 gains: `<slug>` is the spec's file name without `.md`, a
leading `YYYY-MM-DD-` and a trailing `-design`
(`2026-11-15-user-config-audit-design.md` → `user-config-audit`). This
is what recent `/ship` runs already chose (PRs 57, 63 and 64); the runner
computes the same slug to find the child's branch.

### `/ship-many` changes

- **Step 2:** after the duplicate-title check, a spec whose slug repeats
  an earlier spec's is excluded as `duplicate slug` (with `--dry-run`,
  only reported).
- **Step 3:** `--dry-run` prints the `ship-child.py` command per spec.
- **Step 4:** each spec runs as one background Bash command, from the
  main checkout:
  `python "${CLAUDE_PLUGIN_ROOT}/scripts/ship-child.py" --spec <spec> --main <main checkout> --log <log> --name <log-name>`
  (with the usual scripts fallback). The 2-hour limit is the runner's,
  not the Bash tool's; the step says that a background Bash timeout is
  not enforced. The `-2`, `-3` log-name suffix rule is dropped: specs
  with the same file name now share a slug and step 2 excludes the
  later ones.
- **Step 5:** exit code, cost, attempts and `resume` come from
  `<log-name>.status.json`; when the file is missing or not a JSON
  object, the exit code is the background command's, cost and
  attempts are unknown, and the status is decided as if `timed_out`
  were false. `timed out` means the status file's `timed_out` is true. The
  PR lookup by exact title is unchanged.
- **Step 6:** the timed-out recheck goes: the runner killed the child,
  so it is no longer running. The report table gains an `attempts`
  column (`1`, or `2 (resumed)`) and the total cost sums the status
  files.

## Decisions

- **D1. Children get `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0`.** (My
  call.) One setting covers every backgrounded command a child runs
  (suite, `gh run watch`), and it is what made the hand resume finish.
  Rejected: a rule in `/ship` to keep its suite runs in the foreground,
  because a foreground Bash call is itself capped at 10 minutes and the
  other background waits stay exposed. With no ceiling a hung child
  waits forever, which D2's limit bounds.
- **D2. A runner script enforces the limit: 2 hours per attempt, at
  most 2 attempts.** (My call.) A script kills the whole process tree,
  works the same on Windows and macOS (no `timeout` binary on macOS),
  and is unit-tested; prose in `ship-many.md` cannot do that. Each
  attempt gets its own 2 hours, so a resume after a late transient
  failure can still reach CI and the merge; worst case 4 hours per
  child. Rejected: one shared 2-hour budget (a resume late in the
  budget would be killed before it finishes), and a `timeout` wrapper
  in the command line (missing on macOS, leaves grandchildren).
- **D3. Resume once on any ending without a merged PR, a stop-rule
  handoff or a timeout.** (My call.) It also skips the resume when the
  runner cannot check the PR state or find a place to resume (Design,
  point 3). The trigger is "no evidence the
  child stopped on purpose", not a list of error strings: it covers
  `ENOTFOUND`, the print-mode kill and crashes alike, and a stop rule
  (which needs the user) found in the feature worktree is never
  retried. The two stop rules that fire before `/ship` step 2 creates
  the worktree (`git fetch origin` fails in step 1; the spec gate fails
  in step 0) leave no handoff there and are retried on purpose: a fetch
  failure is transient, and `/ship-many` step 2 has already passed the
  spec gate. Rejected: matching transient
  error patterns in the logs (misses new messages, and the print-mode
  kill prints none), and resuming more than once (cost; a second
  failure is likely not transient).
- **D4. The runner requests keep-awake per OS.** (My call.) It needs no
  admin rights, is released when the runner exits, and holds for the
  run's length without the user doing anything. It does not stop sleep
  on a closed laptop lid; the README sentence says so. Rejected: only
  documenting "keep the machine awake" (the failure was an unattended
  run).
- **D5. No ADR-number reservation.** (My call.) The collision happened
  only because a later wave started while an earlier child had ended
  unmerged; with D1 to D3, children that can finish do so before the
  next wave. When it still happens, `/ship` step 9's rule (renumber to
  the next free number, with its file name and index row) handled it in
  this run with no user input. Rejected: reserving numbers in specs at
  gate time (specs written before `/ship-many` would need editing and
  regating), and holding later-wave specs behind an unmerged child
  (changes ADR 0018's "a failing child never stops the others").
- **D6. `/ship` names its branch from the spec file.** (My call.) The
  runner needs the branch to find the worktree and handoff; a fixed
  rule matches current practice and adds no output channel. Rejected:
  having `/ship` print its branch somewhere for the runner to read.
- **D7. Nothing is frozen.** (My call.) The assertions go into test
  files this change creates or must edit.

### ADR

The new ADR records D1 to D6 (one sentence each on the reason
and the rejected option), in the format of
`knowledge/decisions/0000-template.md`, and refers to ADR 0018. For D6
it says that the slug rule is now a contract between `/ship` and
`ship-child.py`, and that `/ship` printing its branch was rejected.

## Testing

`tests/test_ship_child.py` uses fake `claude` and `gh` executables
(small Python scripts in `tmp_path`, run through a `.cmd` or shebang
launcher per OS) and a real temporary git repository with a worktree on
`feat/<slug>`, and asserts:
- the child sees `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` and the exact
  prompt and flags of point 2, and its stdout and stderr land in
  `<name>.json` and `<name>.err`;
- with `--timeout 2` and a fake that sleeps 60 seconds and starts a
  sleeping grandchild, the runner returns within 30 seconds, both
  processes are gone, `timed_out` is true, exit is 124, and no resume
  runs;
- a fake that exits 1 with no PR and no handoff is resumed once in the
  feature worktree (`--resume-wait 0`), writes the `.resume.*` logs,
  and `cost` sums both attempts;
- a handoff in the new worktree whose `Written` line is `by /handoff`
  gives `resume: "stop rule"` and one attempt; a handoff whose
  `Written` line is `by session-end snapshot` (with or without a
  `State refreshed` line) does not block the resume;
- a fake `gh` listing a merged PR created after the start gives
  `resume: "merged"`; one created before the start does not; a `gh`
  that exits non-zero gives `resume: "gh failed"` and one attempt;
- a `feat/<slug>` worktree that existed before the first attempt gives
  `resume: "no worktree"`;
- a `--claude` name that `shutil.which` cannot find exits 2;
- with no worktree, the resume runs in the main checkout when the spec
  is there, and `resume: "no worktree"` when it is not;
- a second failure is not resumed again;
- a non-JSON child stdout gives `cost: null`;
- the slug of `2026-11-15-user-config-audit-design.md` is
  `user-config-audit`, and of `notes.md` is `notes`;
- on Windows only, the real `SetThreadExecutionState` call returns
  non-zero and is reset on exit; elsewhere the keep-awake helper is
  called with the platform's command (subprocess patched);
- bad usage and a missing `--main` exit 2.

`tests/test_ship_many_command.py` gains: step 4 names `ship-child.py`,
`--spec`, `--main`, `--log`, `--name`, and says a background Bash
timeout is not enforced; step 2 names `duplicate slug`; step 5 names
`status.json` and `attempts`; step 6 no longer says a child "may still
be running". The existing child-command assertion moves to the runner:
`ship-child.py` holds the exact prompt and flags.
`tests/test_ship_command.py` gains: step 2 states the slug rule with
the `user-config-audit` example.

## Success criteria

Agreed evaluation and verification criteria:

1. **Suite green:** `pytest`, `ruff check plugin tests` and
   `ruff format --check plugin tests` pass, including every test above,
   on the CI matrix (Windows, Linux, macOS).
2. **Dry run (manual):** `/ship-many --dry-run` on two existing specs
   prints, per spec, the `ship-child.py` command and the log directory,
   and launches nothing.
3. **Runner smoke (manual):** `ship-child.py --timeout 5` with
   `--claude` pointing at a fake that sleeps 60 seconds, run in a real
   terminal, ends within 30 seconds with a status file showing
   `timed_out: true` and `keep_awake: true` on this machine.
4. **Post-merge (not blocking):** the next real `/ship-many` run is
   checked for children that ended without a PR and were not resumed,
   and for any child past 4 hours; the result is recorded in the
   project memory.
