# Duplicate-intent pass in `audit` and `audit-deep`

- **Status:** approved
- **Date:** 2026-11-10

## Purpose

Agent-written code grows functions that do the same thing in different
ways: a new helper is written where an existing one would do, under another
name and with another implementation. Copy-paste detectors miss these
because the text differs. The kit's audits flag "duplication" in their
design pass, but only what a reader happens to notice.

This change adds a duplicate-intent pass to `claude-kit:audit` and
`claude-kit:audit-deep`, adapted from the `finding-duplicate-functions`
skill in obra/superpowers-lab (ideas only; no text or scripts copied): a
script lists the functions, a cheap model sorts them into domains, and a
strong model compares the functions within each domain.

## Scope

**In:**
- `plugin/scripts/function-catalog.py` (new): lists functions as JSON (Design).
- `tests/test_function_catalog.py` (new): unit tests with per-language fixtures.
- `tests/fixtures/function_catalog/` (new): small source files, one or more per language.
- `plugin/skills/audit/duplicates.md` (new): the pass's procedure, read by both audits.
- `plugin/skills/audit/SKILL.md`: a new Pass 4 that follows `duplicates.md`, and a report section.
- `plugin/skills/audit-deep/SKILL.md`: a new Phase H in the main session after Phases B to E; `07-duplicates.md` in the overwrite list and the outputs.
- `plugin/skills/audit-deep/phases/G-report.md`: the inputs include `07-duplicates.md`.
- `plugin/skills/audit-deep/phases/E-design.md`: one line leaving duplicate functions to Phase H.
- `tests/test_audit_skills.py`: assertions for the new pass, phase and output.
- `README.md`: one sentence on the duplicate-intent pass.
- `plugin/.claude-plugin/plugin.json`: minor version bump and the pass named in the description.
- `tests/test_plugin_manifest.py`: the pinned version test follows the bump.
- `docs/superpowers/README.md`: index rows for this spec and its plan (regenerated by `spec-index.py`).

**Out:**
- Consolidating duplicates. The audits are read-only; the report
  recommends a survivor and the user acts on it.
- Syntactic copy-paste detection (jscpd and similar).
- A parser per language. The catalog uses line-based regular expressions;
  missed or spurious functions are acceptable noise for a triage pass.
- Changes to `rules.md` or `check-findings.py`: the pass's findings use the
  existing format.
- The review and guardrails spec (`2026-11-10-review-and-guardrails-design.md`).

## Design

### `plugin/scripts/function-catalog.py`

Standard library only, Python 3.11. It calls
`sys.stdout.reconfigure(encoding="utf-8")` before printing, as
`plugin/scripts/docker-disk.py` does.

Usage: `python function-catalog.py <repo-root> [-o FILE | --split DIR]
[--batch-size N] [--context N] [--include-tests]`. `--split DIR` writes
the same entries as `DIR/batch-001.json`, `DIR/batch-002.json`, and so on,
each a JSON array of at most `--batch-size` entries (default 150), in the
sorted order, and prints the number of batch files.

- Files: `git -C <repo-root> ls-files`, filtered by extension to the
  supported languages. Skipped always: paths with a `node_modules`,
  `vendor`, `dist`, `build`, `.venv` or `third_party` component, and
  `*.min.js`. Skipped unless `--include-tests`: paths with a `test`,
  `tests`, `__tests__` or `spec` component, and file names matching
  `test_*`, `*_test.*`, `*.test.*`, `*.spec.*`.
- Languages and the line pattern that marks a function (multiline mode,
  names captured):

  | Language | Extensions | Matches |
  |---|---|---|
  | Python | `.py` | `def name(` and `async def name(`, any indent |
  | JavaScript / TypeScript | `.js .jsx .mjs .cjs .ts .tsx` | `function name(` (optionally `export`, `default`, `async`); `const` / `let` name `=` an arrow function or `function` expression |
  | Go | `.go` | `func name(` and `func (recv) name(` |
  | Rust | `.rs` | `fn name` with optional `pub`, `pub(crate)`, `async` |
  | Java / C# | `.java .cs` | a line starting with an access modifier (`public`, `protected`, `private`, `internal`) that ends in `name(` before any `=` or `;`, excluding control keywords |
  | Kotlin | `.kt .kts` | `fun name(`, with optional modifiers and receiver |
  | Ruby | `.rb` | `def name` and `def self.name` |
  | Shell | `.sh .bash` | `name() {` and `function name` |
  | PowerShell | `.ps1 .psm1` | `function Name` |

- Names starting with `_` are skipped (private by convention), Python
  dunder methods included (they are protocol, not intent).
- Each entry: `{"file": <repo-relative path>, "line": <1-based>,
  "name": <name>, "language": <language>, "snippet": <the matched line and
  the next N lines, default 15, at most 1,200 characters>}`.
- Output: a JSON array, sorted by file then line, to `-o FILE` or stdout.
  A file that cannot be decoded as UTF-8 is skipped with a stderr line.
- Exit 0 on success (an empty array included); exit 2 on bad usage, a
  root that is not a git repo, or a git failure.

### `plugin/skills/audit/duplicates.md`

The procedure, written for the session that runs the audit (Pass 4 of
`audit`, Phase H of `audit-deep`). All scratch files go in the
`audit-scratch` folder that `rules.md` section 1 allows.

1. **Catalog.** Run `python <CATALOG> <repo> -o <scratch>/catalog.json`,
   where CATALOG is the absolute path of `../../scripts/function-catalog.py`
   from this file's folder. Fewer than 20 entries: the pass writes one line
   (`Skipped: <n> functions, below the 20-function threshold.`) and ends.
   More than 3,000 entries: the pass writes one line (`Skipped: <n>
   functions, above the 3,000-function limit; audit a smaller repo.`) and ends.
2. **Group by domain.** Split the catalog into batches of 150 entries
   (`python <CATALOG> <repo> --split <scratch>/batches`, which writes
   `batch-001.json`, `batch-002.json`, and so on; see the script below).
   Dispatch one subagent per batch, all in one message, each with
   `model: haiku`; if a dispatch is refused because that model is
   unavailable, dispatch that batch again with no model override. Each
   prompt gives its batch path and an output path
   (`<scratch>/categorized-<NNN>.json`), and asks it to assign every entry
   exactly one domain from: files-and-paths, strings-and-formatting,
   validation, errors, http-and-api, dates-and-times, data-transforms,
   storage-and-database, logging, config-and-env, concurrency-and-retry,
   cli-and-processes, ui, crypto-and-ids, git, or `other: <subdomain>`;
   judging by what the function does, not how; adding a one-sentence
   `purpose`; writing every entry (no truncation) via the Write tool as a
   JSON array of `{file, line, name, domain, purpose}` only (no snippets).
   The session joins the outputs back to the catalog by file and line.
   Check each output parses and has as many entries as its batch; on a
   mismatch, dispatch that batch once more, then continue with what parsed
   and note the gap in the report.
3. **Compare within domains.** Domains with 3 or more functions are
   compared, largest first. A domain over 150 entries is split into
   chunks of at most 150 (sorted by file, then line). Each domain or
   chunk is one compare unit; at most 12 units are dispatched, and the
   domains or chunks not compared are listed in the report. Dispatch
   one subagent per unit, all in one message,
   with no model override (the session's model). Each prompt gives the repo
   root, the domain's entries (file, line, name, purpose) and asks the
   subagent to open each function in the repo and return groups of
   functions with the same intent (same inputs to the same result,
   whatever the names or implementation), each with: the intent in one
   line; confidence `HIGH` (same behaviour), `MEDIUM` (same purpose, small
   differences) or `LOW` (related, needs a closer look); the functions as
   `path:line` with the definition line quoted; how they differ; and a
   recommended survivor with the reason (better tests, more callers,
   clearer name). It returns `none` when it finds no group.
4. **Findings.** Each HIGH or MEDIUM group becomes one finding in the
   `rules.md` format: title `Duplicate intent: <intent>`; **Where** the
   recommended survivor's `path:line`; **Evidence** its quoted definition
   line; **Confidence** `verified` only after this session opens each
   cited function and confirms the definition line, else
   `inferred (from: duplicate-intent subagent)`; **Impact** naming the
   other functions as `path:line`; **Fix** "consolidate on the survivor,
   move callers, delete the others; first check the survivor's tests cover
   every caller's use", with effort S or M. Severity: `Medium` when
   functions in the group behave differently on the same input (a caller
   gets a different result depending on which one it calls), else `Low`.
   LOW groups are listed in one table (intent, functions) with no
   findings.
5. Delete the scratch files this pass made (the folder itself is deleted
   at the end of the audit, as `rules.md` says).

### `audit` Pass 4

A new `## Pass 4: duplicate intent` section after Pass 3: follow
`duplicates.md` in this skill's folder. Output gains a
`## Duplicate intent` section after the area sections and before
`## What is missing`, opening with one counts line
(`<n> functions catalogued; <u> of <t> compare units dispatched;
groups: <h> HIGH, <m> MEDIUM, <l> LOW`, or the skip line instead), then
holding the pass's findings, the LOW table, the
domains not compared, or the skip line. These findings enter
`## Fix first` like any other. Pass 3's design check leaves duplicate
functions to this pass (it still reports duplicated blocks inside
functions), so one root cause gets one finding; Phase E of
`audit-deep` gets the same one-line note in `phases/E-design.md`.

### `audit-deep` Phase H

Subagents cannot dispatch subagents, so the pass runs in the main session:
a new `## Phase H: duplicate intent (this session)` after "Wait for all
four" (Phases B to E) and before Phase F. It follows
`../audit/duplicates.md` (from SKILL_DIR) and writes
`REPO/docs/audit/07-duplicates.md`: a header (BAR, the date, then the
counts line or the skip line), then the same content as `audit`'s `## Duplicate intent` section.
Run CHECKER on it as for the other files. Setup step 3's overwrite list
adds `07-duplicates.md`. The Phase G prompt's input range in `SKILL.md`
becomes
`00-repo-map.md` to `06-onboarding.md` and `07-duplicates.md`;
`phases/G-report.md` gains one line naming `07-duplicates.md` as an
area input. Phase F is unchanged. The `07-duplicates.md` header uses
the same counts line as `audit`, and both audits' chat reports repeat
it.

### Version

`plugin.json` gets the next minor version above the one on `origin/main`
when the plan is written; `test_version_is_*` in
`tests/test_plugin_manifest.py` is renamed and updated to it. On a rebase
conflict (the other spec shipped in parallel also bumps it), take the next
minor above `origin/main`'s.

## Decisions

- **D1. Its own spec, shipped with the review spec in one `/ship-many`
  run.** `/ship-many` puts the two in successive waves, because it
  shares `plugin/.claude-plugin/plugin.json` (version and
  description), `tests/test_plugin_manifest.py`, `README.md` and
  `docs/superpowers/README.md` with that spec; on a rebase conflict both
  description additions and both README sentences are kept.
- **D2. Domain grouping on Haiku, comparison on the session's model.**
  Grouping is cheap classification; comparison needs the code read
  closely. This is the kit's first model pin; it is acceptable because
  grouping is a bulk step where a cheaper model costs little accuracy,
  and a missing Haiku falls back to the session's model. Rejected: hard-coding Opus for comparison (the session's model
  is already the strong one in practice, and the kit avoids pinning model
  names elsewhere).
- **D3. Thresholds: skip under 20 or over 3,000 functions; group in
  batches of 150; compare domains with 3 or more, in units of at most
  150 entries; at most 12 compare subagents.** (My call.) The cap bounds the
  token cost of one audit; skipped domains are listed, not hidden.
- **D4. Regex extraction, not parsers.** (My call.) Standard library
  only, every language at once, and a triage pass tolerates noise.
- **D5. Phase H runs in `audit-deep`'s main session.** Phase subagents
  cannot start the per-domain subagents.
- **D6. Severity Medium only when the duplicates behave differently.**
  (My call.) Identical duplicates are a maintenance cost (Low);
  divergent ones are a real risk.

## Testing

`tests/test_function_catalog.py` runs the script on a temporary git repo
built from `tests/fixtures/function_catalog/` (copied, `git init`,
`git add`, commit):

- Each language fixture yields the expected names and lines, including:
  Python `async def` and methods; JS `export default async function`, a
  `const` arrow function and a `function` expression; Go method with a
  receiver; Rust `pub(crate) async fn`; Java and C# methods with
  modifiers, and an `if (` line not matched; Kotlin `fun` with a receiver;
  Ruby `def self.`; shell both forms; PowerShell `function`.
- `_private` names and Python dunders are skipped.
- Test files are excluded by default and included with
  `--include-tests`; a `node_modules` path is always excluded.
- `--context 2` limits the snippet to three lines; snippets never exceed
  1,200 characters.
- The output is sorted by file then line and valid JSON; `-o` writes the
  same JSON to a file.
- `--split DIR --batch-size 2` on five entries writes `batch-001.json` to
  `batch-003.json` holding 2, 2 and 1 entries in sorted order, and prints
  `3`.
- A non-git directory → exit 2.

`tests/test_audit_skills.py` gains:

- `audit/SKILL.md` has `Pass 4` and names `duplicates.md`, and
  `## Duplicate intent`.
- `duplicates.md` exists, names `function-catalog.py`, `haiku`, the
  20-function threshold, the 3,000-function limit, batches of 150,
  compare units of at most 150, the cap of 12, the counts line, `audit-scratch`, and the
  `HIGH`/`MEDIUM`/`LOW` levels.
- `audit-deep/SKILL.md` has `Phase H`, names `07-duplicates.md` and
  `../audit/duplicates.md`; `G-report.md` names `07-duplicates.md`.
- The relative path from `duplicates.md` to `function-catalog.py`
  resolves.

## Success criteria

1. `pytest` passes, including the tests above; check: `pytest`.
2. `ruff check plugin tests` and `ruff format --check plugin tests` are
   clean; check: run both.
3. `python plugin/scripts/function-catalog.py .` on this repo prints a
   JSON array with at least 50 entries, all from `plugin/` (tests
   excluded); check: run it and count.
4. Live check after merge: run `claude-kit:audit` on this repo and record
   Pass 4's counts line (functions catalogued, compare units
   dispatched, groups by HIGH, MEDIUM and LOW) in `/ship`'s final report (they also appear in
   `docs/audit/audit.md`); `check-findings.py` exits 0 on the audit
   file; check: run both.
5. No username or private repo name is in the diff; check:
   `git diff origin/main | grep -i -E "<pattern>"` returns nothing, where
   `<pattern>` is the machine's username plus every name from
   `gh repo list --visibility private --json name -q ".[].name"`, joined
   with `|`.
6. The PR is squash-merged by `/ship` with green CI; check: `gh pr checks`
   and `/ship`'s step 10 verification.
