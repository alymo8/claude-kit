# Docker Desktop disk upkeep on Windows

- **Status:** approved
- **Date:** 2026-10-21

## Purpose

On Windows, Docker Desktop keeps all its data in one virtual disk,
`%LOCALAPPDATA%\Docker\wsl\disk\docker_data.vhdx`. The file grows as Docker
writes data but does not shrink when data is deleted, unless the WSL distro
is set to sparse. On 2026-10-21 the file on the kit owner's machine was
38.7 GB for about 9.7 GB of data. Pruning freed space inside the disk but not
on C:, and only an elevated `diskpart` `compact vdisk` got the file back to
9.5 GB. After that compaction the file was 9.5 GiB, the ext4 file system inside
it used 3.2 GiB, `docker system df` counted about 1.7 GB (decimal units, about 1.6 GiB), and the file was
not sparse.

This change does three things:

- tells every Windows user, once, how to stop the growth (sparse distro, an
  optional build-cache cap);
- adds a read-only status line to the Docker clean-up in `/ship` and
  `/ship-fast`, so growth is noticed;
- adds an on-demand `/docker-compact` command that reclaims the space after
  asking.

The bloat is machine-wide, not tied to one feature, and compacting stops
Docker and needs a UAC prompt. So compaction stays out of the per-feature
clean-up, which `/ship` runs without check-ins.

## Design

### `plugin/scripts/docker-disk.py`

Standard library only, Python 3.11, in the style of the other scripts
(module docstring with usage, `main()` returning the exit code). It always
exits 0 and never changes anything: no writes, no starting a WSL distro, no
Docker command other than `docker system df`.

1. **Platform.** If `sys.platform != "win32"`, print
   `docker disk: skipped (not Windows)` and exit.
2. **Disk file.** Use the first that exists:
   `%LOCALAPPDATA%\Docker\wsl\disk\docker_data.vhdx`, then
   `%LOCALAPPDATA%\Docker\wsl\data\ext4.vhdx` (older Docker Desktop). If
   neither exists, print `docker disk: skipped (no Docker Desktop disk found)`
   and exit.
3. **File size** from `os.stat(path).st_size`.
4. **Sparse** from `os.stat(path).st_file_attributes &
   stat.FILE_ATTRIBUTE_SPARSE_FILE`. This needs no subprocess and does not
   depend on the Windows display language, unlike `fsutil` output.
5. **Used space inside the disk.** Only if the `docker-desktop` distro is
   already running: `wsl -l --running -q` (its output is UTF-16-LE; decode
   it and strip NULs) lists `docker-desktop`. Then run
   `wsl -d docker-desktop -- df -B1 /mnt/docker-desktop-disk` and take the
   `Used` column of the data row, in bytes. If the distro is not running, or
   any step fails, used is unknown. The script never starts the distro.
6. **Docker total.** Run `docker system df`. Sum the `SIZE` column over the
   Images, Containers, Local Volumes and Build Cache rows. Sizes use Docker's
   decimal units (`B`, `kB`, `MB`, `GB`, `TB`, factors of 1000). If `docker`
   is missing, the daemon is down, or the output does not parse, the total
   is unknown.
7. Every subprocess call has a 15-second timeout; a timeout counts as
   unknown for that value.

**Output.** One line. Sizes are in GiB (bytes / 2^30) with one decimal, so
they match what Explorer and `df -h` show. An unknown value prints as `<label> ?`, with no unit (for example
`used ?`):

```
docker disk: file 9.5 GiB, used 3.2 GiB, docker 1.6 GiB, sparse no -> not sparse; compact suggested (/docker-compact)
```

**Verdict.** A list of flags, joined with `; `, or `ok` when the list is
empty:

- `not sparse` when the sparse bit is clear.
- `compact suggested (/docker-compact)` when used is known and
  `file > 1.5 × used` **and** `file − used > 2 GiB` (D1). When used is
  unknown, this flag is never set.

The Docker total is shown for context only; it is not used in the verdict
(D4).

### `plugin/commands/docker-compact.md`

Frontmatter: `description:` and `disable-model-invocation: true` (it is
side-effecting, so only the user invokes it, like `/ship`). On a system that is not Windows, the
command says it does not apply and stops. Otherwise:

1. Run `python "${CLAUDE_PLUGIN_ROOT}/scripts/docker-disk.py"` (fallback
   `~/.claude/skills/claude-kit/scripts/docker-disk.py`) and show its line.
   If the verdict has no `compact suggested`, say so (and, when used is
   `?`, say that the distro was not running), then continue to step 2: the
   user decides.
2. **Ask the user before anything else.** Say that compacting stops Docker
   Desktop and every container, and needs one UAC prompt. Wait for a clear
   yes. A no ends the command with nothing changed.
3. If the `docker-desktop` distro is running, trim the free space so the
   compaction can reclaim it:
   `wsl -d docker-desktop -- fstrim -v /mnt/docker-desktop-disk`. A failure
   is reported, not fatal.
4. Ask the user to quit Docker Desktop from its tray icon and confirm. Then
   run `wsl --shutdown`.
5. If the script said `not sparse`, offer (as a separate yes/no) to run
   `wsl --manage docker-desktop --set-sparse true` now, while Docker is
   quit.
6. Create `%TEMP%\dcompact` and write `compact.txt` in it with:
   `select vdisk file="<disk path>"`, `attach vdisk readonly`,
   `compact vdisk`, `detach vdisk`. The folder is a short, fixed path on
   purpose: on 2026-10-21, writing the script under the session scratchpad
   with `Set-Content` failed on a long-path error, and a short path also
   avoids quoting problems with diskpart's `/s`.
7. Note the file size, then run
   `Start-Process diskpart -ArgumentList '/s', '<%TEMP%\dcompact\compact.txt>' -Verb RunAs -Wait`.
8. Delete `%TEMP%\dcompact`, whether or not diskpart succeeded.
9. Report the file size before and after. Tell the user to start Docker
   Desktop again, then run the script once more for the full line.

The command never removes Docker objects, never runs a prune, and never
touches volumes. Compaction only gives back unused blocks of the disk file.

### Clean-up in `/ship` and `/ship-fast`

In `/ship` step 11, after `docker buildx rm <slug>`: when the task used
Docker, run `python "${CLAUDE_PLUGIN_ROOT}/scripts/docker-disk.py"` (same
fallback path) and keep its line. It never prompts, and its verdict is not a
stop rule. Step 12's report includes the line when the task used Docker.

In `/ship-fast`'s clean-up section, after `docker buildx rm <slug>`, and only
when the task used Docker: the same script call, and its line goes in the clean-up reply.

The existing sentences about the label filter and the baseline stay
word for word.

### Setup note: `docs/setup.md`

A new `## Docker Desktop on Windows` section, placed after `## Switches`.
It says the disk file grows and does not shrink unless the distro is
sparse. It covers:

- the one-time fix: quit Docker Desktop, then run
  `wsl --manage docker-desktop --set-sparse true`;
- an optional cap on the build cache in Docker Desktop → Settings → Docker
  Engine: `"builder": {"gc": {"enabled": true, "defaultKeepStorage": "5GB"}}`;
- that the kit never changes these settings itself;
- that `docker-disk.py` shows the state and `/docker-compact` reclaims
  space that has already built up.

### `CLAUDE.md`

One sentence appended to the Docker paragraph, after the prune rule: the
clean-up also runs `plugin/scripts/docker-disk.py` (which reports only on
Windows) and reports its line, and compaction is only on demand through `/docker-compact` (ADR 0038).

### ADR 0038

Title: "Docker disk upkeep runs outside the per-feature clean-up". It
records: the bloat is machine-wide; compacting stops Docker and needs UAC,
which conflicts with `/ship`'s no-check-in run; the sparse flag is the
prevention and compaction is the repair; and the threshold is measured
against the space used inside the disk, not `docker system df` (D4).

## Decisions

- **D1. Compact threshold: file > 1.5 × used and file − used > 2 GiB.**
  The second condition stops it suggesting compaction of small disks, where
  the gain is not worth stopping Docker. Rejected: the ratio alone.
- **D2. No live compaction in this change.** It needs UAC and stops Docker,
  and the owner compacted on 2026-10-21. Rejected: a live run as an
  acceptance check.
- **D3. Spec, spec gate, then `/ship`.** This is the kit's normal path.
  Rejected: building on a branch and stopping at the PR.
- **D4. Measure against the space used inside the disk, not
  `docker system df`.** The latter leaves out data that is in the disk
  (1.6 GiB counted against 3.2 GiB used), so a ratio against it would
  suggest compaction almost every time. Rejected: the prompt's
  `docker system df` threshold.
- **D5. Report-only line in the clean-up; compaction is a separate
  command.** `/ship` runs without check-ins, and the bloat is not caused by
  one feature. Rejected: offering to compact inside the clean-up.
- **D6. Sparse bit from file attributes, not `fsutil`.** It needs no
  subprocess and does not depend on the display language. Rejected: parsing
  `fsutil sparse queryflag` output.
- **D7. The script never starts the `docker-desktop` distro.** Starting it
  is a side effect of a status check. If the distro is not running, used is
  `?` and no compaction is suggested.

## Testing

`tests/test_docker_disk.py` covers the script, with `subprocess.run`,
`os.stat` and the platform faked (no real Docker or WSL needed, so it runs
in CI on Linux):

- Not Windows → the skipped line, exit 0.
- No disk file at either path → the no-disk line, exit 0.
- The fallback path `ext4.vhdx` is used when `docker_data.vhdx` is missing.
- Sparse bit set and clear → `sparse yes` / `sparse no` and the
  `not sparse` flag.
- `df -B1` output → used in bytes, and the GiB formatting.
- `docker system df` output with `B`, `kB`, `MB` and `GB` sizes → the right
  total.
- `wsl -l --running -q` UTF-16-LE output with and without `docker-desktop`;
  without it, `df` is not called and used is `?`.
- `docker` missing (`FileNotFoundError`), daemon down (non-zero exit), and a
  timeout → `docker ?`, exit 0.
- Across all cases, the faked `subprocess.run` sees only
  `wsl -l --running -q`, `wsl -d docker-desktop -- df -B1
  /mnt/docker-desktop-disk` and `docker system df` (criterion 4).
- Threshold edges: over 1.5× with a gap over 2 GiB → suggested; over 1.5× with a
  gap of 2 GiB or less → not suggested; 1.5× exactly → not suggested; used
  unknown → not suggested; nothing flagged → `ok`.

`tests/test_docker_compact_command.py` checks that the command text has: a
frontmatter description, `docker-disk.py`, an ask before stopping Docker,
`fstrim`, `wsl --shutdown`, `--set-sparse true`, `%TEMP%\dcompact`, the four
diskpart lines, `-Verb RunAs`, deleting the temp folder, and no `prune`.

`tests/test_ship_command.py` and `tests/test_ship_fast_command.py` check
that `docker-disk.py` appears in the clean-up step, and that the existing
rule text is still there: in `ship.md`, "Never run a prune without a" and
"never remove anything in the baseline"; in `ship-fast.md`, "never run a
prune without a" (lower case there, mid-sentence).

## Success criteria

1. `pytest` passes, including the new tests above; check: `pytest`.
2. `ruff check plugin tests` and `ruff format --check plugin tests` are
   clean; check: run both.
3. Dry run on the owner's machine, with Docker Desktop running:
   `python plugin/scripts/docker-disk.py` prints the file size, used space,
   Docker total and sparse state. Each number must be within 0.1 GiB of a
   manual reading taken at the same time (`(Get-Item <vhdx>).Length/1GB`,
   `df` inside `docker-desktop`, and the four `docker system df` SIZE values
   summed in decimal units, then divided by 2^30), and the sparse state must
   match
   `fsutil sparse queryflag`. On 2026-10-21 that expects about 9.5 / 3.2 /
   1.6 GiB, `sparse no` and `not sparse; compact suggested`. Check: run the
   script and the manual commands, and paste both outputs into the PR.
4. The script changes nothing: a test asserts that the only subprocess
   commands it runs are `wsl -l --running -q`,
   `wsl -d docker-desktop -- df -B1 …` and `docker system df`. Check:
   `pytest tests/test_docker_disk.py`.
5. The existing Docker safety rules are unchanged in `CLAUDE.md`,
   `ship.md` and `ship-fast.md`; check: the tests above, plus
   `git diff main -- CLAUDE.md plugin/commands` shows no removed rule
   sentence.
6. No username or private repo name is in the diff; check:
   `git diff main | grep -i -E "<pattern>"` returns nothing except the
   public GitHub owner in existing URLs, where `<pattern>` is the machine's
   username (`$env:USERNAME`) plus every name from
   `gh repo list --visibility private --json name -q ".[].name"`, joined
   with `|`.
7. The PR is open with green CI, then squash-merged by `/ship`; check:
   `gh pr checks` and `/ship`'s step 10 verification.
