# Personal vault Implementation Plan

- **Status:** approved
- **Date:** 2026-11-10

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a personal-vault template, `/vault-init`, a `vault-pending.py` change detector, the `ingest` and `task-prompt` skills and a SessionStart hook that points every session at the vault when `CLAUDE_KIT_VAULT` is set.

**Architecture:** The template lives in `plugin/templates/vault/` and is copied by a standard-library script, `plugin/scripts/vault-init.py`, which writes `vault.toml` and `.gitignore` per profile and makes one git commit. `plugin/scripts/vault-pending.py` compares `raw/` files with the `raw`/`sha256` frontmatter of `wiki/sources/*.md` and also extracts `.docx` text. Two Markdown skills drive the LLM work; a new hook, `plugin/hooks/vault_inject.py`, injects one line. Docs, ADR 0040 and a minor version bump (0.27.1 to 0.28.0) finish the change.

**Tech Stack:** Python 3.11+ standard library (`tomllib`, `zipfile`, `xml.etree`, `hashlib`), pytest, ruff, Markdown, JSON, git.

**Spec:** `docs/superpowers/specs/2026-11-10-vault-design.md`

### Plan-level answers to the spec gate's plan questions

- **Source and task file dates:** a source page's `date` and its file-name
  prefix (`YYYY-MM-DD-<slug>.md`) are the date the material itself states
  (the call date, a page's publication date, a document's date); when it
  states none, the ingest date. A task file is named
  `<source page date>-<slug of the action item>.md`, so it uses the same
  rule. (Task 4)
- **`aliases: []`:** `person.md` and `topic.md` carry `aliases: []`
  (Obsidian's alias property); ingest searches page names and aliases.
  (Task 1, Task 4)
- **Frontmatter parsing:** `read_frontmatter` strips whitespace and one pair
  of matching surrounding `"` or `'` quotes; `pending` normalizes each `raw`
  value to a posix path (`\` becomes `/`, a leading `./` is dropped) before
  comparing it with the walk's paths. Ingest writes `raw` as a vault-relative
  posix path. (Task 2, Task 4)
- **`raw/` walk and vanished raw files:** the walk is recursive
  (`raw/web/2026/x.md` counts) and skips any path with a component starting
  with `.` (dotfiles and dot-directories). A source page whose `raw` file no
  longer exists is reported with status `missing` (text line
  `missing\t<raw path>`, JSON `source` = the page, `sha256` = null). The
  ingest skill lists `missing` entries in its report and leaves those pages
  unchanged; the user decides. (Task 2, Task 4)
- **`--extract` and `VAULT`:** they are exclusive. `--extract FILE` together
  with `VAULT` or with `--json` is a usage error (`parser.error`, exit 2), and
  so is a call with neither. (Task 2)
- **vault-init failures:** a failed git command or an `OSError` (for example
  `git` not on `PATH`) after the copy removes what vault-init wrote (the
  whole destination if vault-init created it; its contents, `.git`
  included, if it pre-existed empty), prints `error: ...` to stderr and
  exits 1. When `git config --get user.name` or `user.email` fails, the commit
  runs with `-c user.name=claude-kit -c user.email=claude-kit@localhost`
  (`scaffold.py`'s rule); it never writes git config. Tests set no identity
  except the fallback test, which runs with an empty global config. (Task 1)
- **`.gitignore`:** generated by `vault-init.py` only; the template folder has
  no `.gitignore` and no `vault.toml`, so profile values live in one place
  (`PROFILES` in the script). (Task 1)
- **Work profile ignore:** `raw/`, exactly as the spec's `git_ignore`, so a
  clone of a work vault has no `raw/` folders (ingest and `vault-pending.py`
  treat a missing `raw/` as no raw files). The test asserts with
  `git ls-files` that the personal commit holds the whole rendered tree and
  the work commit holds the tree minus every `raw/` entry. (Task 1)
- **`.gitattributes`:** the template ships one, holding the single line
  `raw/** -text`, so line-ending conversion on checkout never changes a raw
  file's bytes and hash. (Task 1)
- **Task `owner` and `topic`:** quoted wiki-links like `source`
  (`owner: "[[Tobias Renn]]"`, `topic: "[[Project Atlas]]"`), empty when not
  stated. `topic` is the topic the action item is about; when unclear, the
  first entry of the call's source-page `topics`; empty when the call has
  none. Task-prompt follows these links one hop. (Task 4)
- **Changed raw files:** ingest updates the existing source page, adds what
  the new version states, and removes from person and topic pages each fact
  that links to that source page and the new version no longer states; every
  removal is listed in the report. (Task 4)
- **Task-prompt with no match:** it says no task matched, lists the open tasks
  (status not `done`) by file name, and stops. (Task 4)
- **`user_only`:** `vault-init` is not added to the `user_only` set in
  `tests/test_plugin_manifest.py`; `tests/test_vault_skills.py` checks its
  `disable-model-invocation: true`. (Task 4)
- **Printed hook path:** the env value as given, converted with
  `Path(value).as_posix()` (not resolved), so a trailing separator is dropped
  and backslashes become `/`. (Task 3)

### Other plan-level choices

argparse: positional `path`, `--profile` with `choices=list(PROFILES)`,
default `personal` (argparse's own exit 2 covers a bad profile and a missing
path). Order in `main`: parse; refuse with exit 1 and an `error: ...` stderr
line if `path` exists and is a file or a non-empty directory; then
`shutil.copytree(TEMPLATE, path, dirs_exist_ok=True)`; write `vault.toml`
(`vault_toml`: three lines `profile = "<p>"`,
`registries = ["people", "topics", "sources"]`, `git_ignore = [...]` with
JSON-style quoted strings) and `.gitignore` (`gitignore`: the profile's
`git_ignore` entries then `OBSIDIAN_IGNORE`, one per line, trailing newline);
then `git init -q -b main`, `git add -A`, `git [identity] commit -q -m
"Scaffold vault from claude-kit"` with the identity fallback copied from
`scaffold.py`'s `commit_all` (without its hook steps); every git call goes
through the module-level `git` function. The `git config --get` probes only
choose the identity flags (their non-zero exit is the normal path into the
fallback). A non-zero return code from `init`, `add` or `commit`, or an
`OSError` from any git call (for example `FileNotFoundError` when `git` is
not on `PATH`) after the copy: remove what was written (`shutil.rmtree(path)`
if `main` created `path`; otherwise delete every child of `path`, `.git`
included), using an error handler that clears the read-only bit and retries
(Windows marks `.git/objects` files read-only), passed as `onexc=` on Python
3.12+ and `onerror=` on 3.11 (`sys.version_info` check), then print
`error: git <cmd> failed: <stderr>` (or `error: <exc>`) to stderr and return
1. Finally
print the vault path and three next-step lines: set `CLAUDE_KIT_VAULT` to the
path under `env` in `~/.claude/settings.json`; open the folder as a vault in
Obsidian; create the remote yourself with `gh repo create --private`.
