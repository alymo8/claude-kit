**F1. [High] The SessionEnd snapshot hook runs at the edge of the 1.5 s SessionEnd budget and has no `timeout`.** [inferred from measurement plus docs]

- `plugin/hooks/hooks.json:33-41`:
  ```json
  "SessionEnd": [
    {
      "hooks": [
        {
          "type": "command",
          "command": "python \"${CLAUDE_PLUGIN_ROOT}/hooks/handoff_snapshot.py\""
        }
      ]
    }
  ],
  ```
- The hooks reference: "`SessionEnd` hooks share a 1.5-second budget; if your settings set a longer per-hook `timeout`, Claude Code raises the budget to match, up to 60 seconds."
- Measured on this machine, in this repo, read-only: `python plugin/scripts/handoff.py state` took 988 ms and 1055 ms on two runs; `gh pr view --json url` alone took 764 ms; bare Python start-up took 195 ms. The hook adds the transcript tail read on top. That is roughly 1.2 to 1.5 s against a 1.5 s budget. On a slow network, a cold disk, or a large repo `git status` the hook is killed before `path.write_text` at `plugin/scripts/handoff.py:165`, and because the write is the last step, nothing is written and nothing is reported (ADR 0007: hooks never surface errors).
- The file `.claude/handoffs/main.md` written at `14:13 by session-end snapshot` shows it completes sometimes. It does not show it completes reliably.
- The cost is silent: the State section a fresh session trusts ("verify it against git before trusting it", `handoff_inject.py:24-28`) goes stale.
- Fix, two parts. Raise the budget in `hooks.json`:
  ```json
  "SessionEnd": [
    {
      "hooks": [
        {
          "type": "command",
          "command": "python \"${CLAUDE_PLUGIN_ROOT}/hooks/handoff_snapshot.py\"",
          "timeout": 20
        }
      ]
    }
  ],
  ```
  and stop paying for `gh` when it cannot have an answer, in `plugin/scripts/handoff.py:73-90`:
  ```python
  def pr_url(cwd: Path, upstream: str | None) -> str | None:
      """URL of the open PR for the current branch via gh, or None."""
      if not upstream or not shutil.which("gh"):
          return None
      ...
  ```
  and pass `upstream` from `state_section` (it is already computed at line 99). A branch with no upstream has no PR; `main` rarely does either, so most session ends skip the 0.8 s network call.

**F2. [Medium] The spec-index hook never fires for edits made through Bash, which is how auto mode tells Claude to edit files.** [verified]

- `plugin/hooks/hooks.json:5`: `"matcher": "Write|Edit",`
- `plugin/hooks/on_spec_edit.py:21`: `TARGET_RE = re.compile(r"(^|/)docs/superpowers/(specs|plans)/[^/]+\.md$")` reads `tool_input.file_path`, a field that only the file tools carry.
- This session's harness instructions say: "While auto mode is active: Do your work through the Bash tool wherever it can accomplish the job ... make file changes with sed, heredocs, or short scripts, rather than using the dedicated Read, Edit, or Write tools." A spec written with a heredoc, `sed -i`, or `git mv` never triggers the hook, so `docs/superpowers/README.md` silently drifts, which is the exact failure the index hook was built to prevent (`docs/superpowers/specs/2026-09-15-project-scaffolder-design.md:249-250`: "the HTML drift showed that 'remember to run it' fails").
- The `/ship` command commits a plan (`plugin/commands/ship.md:40-42`) and, in auto mode, will do so via Bash.
- Fix: keep the PostToolUse hook and add a cheap, idempotent regeneration at a point that does not depend on which tool wrote the file. `spec-index.py` already writes nothing when the content is unchanged (`plugin/scripts/spec-index.py:67-68`), so running it at every Stop is safe:
  ```json
  "Stop": [
    {
      "hooks": [
        {
          "type": "command",
          "command": "python \"${CLAUDE_PLUGIN_ROOT}/scripts/spec-index.py\" \"${CLAUDE_PROJECT_DIR}/docs/superpowers\""
        }
      ]
    }
  ]
  ```
  `spec-index.py:63-64` returns without writing when neither `specs/` nor `plans/` exists, so this is a no-op in repos without specs. Add a test in `tests/test_plugin_manifest.py` that the `Stop` entry exists.

**F12. [Low] `worktree_audit.py` uses the process cwd instead of the event's `cwd`, unlike its sibling hooks.** [verified]

- `plugin/hooks/worktree_audit.py:115`: `text = report(Path.cwd())`
- `plugin/hooks/handoff_inject.py:77`: `cwd = Path(event.get("cwd") or Path.cwd())`
- It works today because hook processes start in the project directory. It is the one hook that ignores stdin entirely, which also means it never reads `hook_event_name` or the matcher; it runs on `compact` and `resume` too, re-printing the same leftover block after every compaction. Harmless, but inconsistent. Fix: read stdin like the others and pass the event `cwd`; optionally set `"matcher": "startup|clear"` on it as well.

Everything else about the hooks is fine: matchers are valid, the always-exit-0 contract is honoured in every handler (`try/except Exception` around the whole body), stdin is parsed defensively, paths are normalised for backslashes (`on_spec_edit.py:36`), git is invoked as an argv list never a shell string, and the transcript is read from the tail only (`_transcript.py:20-34`).

**F3. [High] Every command is model-invocable, including `/ship`, which squash-merges to `main` without check-ins.** [verified]

- `plugin/commands/ship.md:1-4`:
  ```
  ---
  description: Use after a spec is approved to land it on main without further check-ins — plan, implement, CI, review, PR, green CI, squash-merge, verify main, clean up
  argument-hint: [path-to-spec.md]
  ---
  ```
- The frontmatter has no `disable-model-invocation`. The plugins guide shows `disable-model-invocation: true` as the field that makes a skill user-only. Without it the command is listed in every session's skill catalogue (this session lists `claude-kit:ship` with the description above), so the model can decide on its own that a spec "is approved" and start a merge pipeline. `CLAUDE.md:158` says invoking `/ship` "is my instruction"; that guarantee only holds if only you can invoke it.
- The same applies, with lower stakes, to `/new-project` (creates a repo and commits), `/adopt-conventions` (writes files into the current repo) and `/spec-html` (opens a browser). `/handoff` should stay model-invocable because the nudge text tells Claude to run it.
- Fix, `plugin/commands/ship.md:1-4` (and the same line in `new-project.md`, `adopt-conventions.md`, `spec-html.md`):
  ```
  ---
  description: Use after a spec is approved to land it on main without further check-ins — plan, implement, CI, review, PR, green CI, squash-merge, verify main, clean up
  argument-hint: [path-to-spec.md]
  disable-model-invocation: true
  ---
  ```
  Side benefit: descriptions of user-only skills are not loaded into the model's catalogue, which trims a little from every session.

**F14. [Low] `commands/` is the legacy layout, and every command carries the same fallback boilerplate.** [verified]

- Plugins reference: "`commands/` | Skills as flat Markdown files. Use `skills/` for new plugins."
- `plugin/commands/handoff.md:17-18`: "(Fallback if the variable is not expanded: `~/.claude/skills/claude-kit/scripts/handoff.py`.)" and the same in `new-project.md:15-16`, `adopt-conventions.md:15-16`, `spec-html.md:10-11`.
- The plugins reference says placeholders resolve "Anywhere the placeholder appears" in skill content, so the fallback has never been needed. Four copies of a workaround for a problem that does not exist is noise the model reads on every invocation.
